macOS 13 or later

The universal app runs on Intel and Apple Silicon; the single-architecture ones are half the size.

  1. Unzip and open unfr0zen.app.
  2. It isn't notarized, so macOS blocks the first launch. Allow it under System Settings → Privacy & Security, or run:
xattr -dr com.apple.quarantine unfr0zen.app

The command-line tool is the app's own executable, run with arguments:

unfr0zen.app/Contents/MacOS/unfr0zen --help

Windows 10 or later

  1. Unzip and run unfr0zen.exe.
  2. It isn't signed, so SmartScreen may warn you: More info, then Run anyway.
1st and 2nd gen thermostats: the boot ROM (0451:d00e) needs the WinUSB driver, bound once with Zadig.
3rd gen: if a run stops with ACM interface for 18d1:4ee0 did not appear, an Android driver installed earlier has claimed the recovery device. While the thermostat is in recovery, open Device Manager, find Android Bootloader Interface, choose Update driver → Browse my computer → Let me pick → Universal Serial Bus devices → USB Composite Device. The choice persists; run again.

Linux (glibc 2.28+)

tar xf unfr0zen-linux-*.tar.gz && ./unfr0zen

With arguments, the same executable is the command-line tool, for a terminal, SSH or a headless machine: ./unfr0zen --help.

USB access (once)

Without this udev rule only root can open the thermostat. Reconnect the unit afterwards if it's already plugged in.

sudo tee /etc/udev/rules.d/70-unfr0zen.rules > /dev/null <<'EOF'
# i.MX ROM serial download, recovery U-Boot
ATTRS{idVendor}=="15a2", ATTRS{idProduct}=="0071", TAG+="uaccess", ENV{ID_MM_DEVICE_IGNORE}="1"
ATTRS{idVendor}=="15a2", ATTRS{idProduct}=="007d", TAG+="uaccess", ENV{ID_MM_DEVICE_IGNORE}="1"
ATTRS{idVendor}=="18d1", ATTRS{idProduct}=="4ee0", TAG+="uaccess", ENV{ID_MM_DEVICE_IGNORE}="1"
# unfr0zen initramfs shell and the Nest application's console
ATTRS{idVendor}=="0525", ATTRS{idProduct}=="a4a7", TAG+="uaccess", ENV{ID_MM_DEVICE_IGNORE}="1"
ATTRS{idVendor}=="0525", ATTRS{idProduct}=="b4a4", TAG+="uaccess", ENV{ID_MM_DEVICE_IGNORE}="1"
ATTRS{idVendor}=="2464", ATTRS{idProduct}=="0030", TAG+="uaccess", ENV{ID_MM_DEVICE_IGNORE}="1"
ATTRS{idVendor}=="2464", ATTRS{idProduct}=="0031", TAG+="uaccess", ENV{ID_MM_DEVICE_IGNORE}="1"
# Diamond/j49: OMAP boot ROM (and x-loader, the flasher), each application's gadget
ATTRS{idVendor}=="0451", ATTRS{idProduct}=="d00e", TAG+="uaccess", ENV{ID_MM_DEVICE_IGNORE}="1"
ATTRS{idVendor}=="2464", ATTRS{idProduct}=="0001", TAG+="uaccess", ENV{ID_MM_DEVICE_IGNORE}="1"
ATTRS{idVendor}=="2464", ATTRS{idProduct}=="0002", TAG+="uaccess", ENV{ID_MM_DEVICE_IGNORE}="1"
EOF
sudo udevadm control --reload-rules && sudo udevadm trigger

You'll need

  • A Nest Learning Thermostat, 2nd or 3rd generation, or a 1st generation Diamond for experimental recovery.
  • A USB data cable: mini-USB for 1st gen, micro-USB for 2nd and 3rd gen. A charge-only cable won't work.
  • For MQTT: an MQTT broker (for example the Mosquitto add-on) and Home Assistant's MQTT integration.
  • For Matter: Home Assistant's Matter integration.
  • For Zigbee: a Zigbee coordinator. Zigbee2MQTT 2.12.1 or later with the unfr0zen converter is recommended; ZHA works too.

Install

Optional: a NAND backup lets you restore the thermostat as it was, should you want that one day. Choose Back up NAND from the menu beside Start, or run unfr0zen backup; the USB steps are the same as below. See Backup & restore.
  1. Open unfr0zen and tick Relay to MQTT broker (host or host:port, with user, password and TLS as needed), Matter, Zigbee, or several. Any of them replaces the thermostat's Nest cloud connection: the Nest and Google Home apps no longer control it. Optionally block Nest's and Google's servers, set an NTP server, and turn on SSH (root password unfr0zen by default).
  2. Click Start.
  3. Take the display off its base and connect its USB port to the computer. The generation is detected automatically.
  4. When the app asks, hold the front button for 10 seconds.
  5. Wait a few minutes until it's done, then put the display back on its base.
  6. For MQTT or Matter, join the thermostat to Wi-Fi from its own menu (Settings → Network) if it isn't already. The network doesn't need internet access.
